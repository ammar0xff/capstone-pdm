Industrial Problem & Motivation

The Real-World Crisis: Unplanned Factory Shutdowns

Unexpected induction-motor failures can stop a production line. This project reports measured condition changes locally so an operator can act before a fault is confirmed physically.

Reactive Maintenance
"Run it until it fails." Can damage shafts and stop production. The cost impact was not measured in this project.
Preventive Maintenance
"Replace on a fixed calendar." Can replace parts that are still healthy and introduces assembly risk during unnecessary teardowns.
Our Predictive Paradigm
"Act when the measured state changes." Continuous multi-modal monitoring reports the current class and lets the operator decide. Remaining life on our rig still needs our own run-to-failure data.

Why Edge Computing over Pure Cloud?

Streaming every raw window would increase bandwidth and expose raw signals; an offline link would also break the live view. Features are computed on the Pi and lightweight status frames are mirrored. Inference has no verified latency yet on the Raspberry Pi 4; cloud cost and end-to-end latency were not measured.

The 0-EGP Cloud Philosophy

Telemetry uses the Firebase Spark tier configured for this project; no paid server was added. Synchronisation latency and actual billing were not measured, so no cost or timing claim is made.

Edge Artificial Intelligence

Two-Stage Coarse-to-Fine Inference Gating

Based on the Cyber-Physical System design by Cinar et al. (2022): a statistical gate avoids classifier calls during normal operation. CPU and energy savings were not measured on our rig.

STAGE 1: COARSE GATING gate timing not benchmarked
Shewhart Statistical Process Control (SPC)

Tracks the rolling baseline mean ($\mu$) and variance ($\sigma$) of the machine. When the vibration envelope satisfies:

z = |x - μ| / σ ≤ 3.0

the gate reports no anomaly and the classifier is not called. Power and thermal savings were not measured.

STAGE 2: FINE DIAGNOSTICS not yet measured on the Pi
Random Forest classifier

When Stage 1 detects a $3\sigma$ violation or kurtosis shock, Stage 2 classifies the current state:

• Healthy (Class 0): normal baseline.
• Mechanical Imbalance (Class 1): $1\times$ RPM signature.
• Bearing Defect (Class 2): high-kurtosis impacts.
• Thermal Runaway (Class 3): sustained temperature rise.

Physics & Waveform Kinematics

Nine Input Features & Diagnostic Physics

The classifier uses features motivated by the vibration literature, including Randall & Antoni (2011). These are model inputs, not field-calibrated failure thresholds.

Kurtosis ($K$) — Shock Physics

Kurtosis is the fourth standardised moment. In the synthetic generator, bearing-impact windows occupy a higher kurtosis range than healthy windows; no field threshold is claimed.

Crest Factor ($CF$)

$$CF = \frac{x_{\text{peak}}}{x_{\text{rms}}}$$ Peak divided by RMS. It highlights sharp impacts in the benchmark features; lead time before a real bearing fault was not measured.

Standards as references

ISO 20816 and ISO 10816-3 are cited as vibration-diagnostics background. Their zone values are not used as this rig's calibration constants or physical failure thresholds.

Engineering Robustness

Offline-First Resiliency: What If Internet Dies?

The Pi keeps sampling and deciding locally when the cloud link is unavailable. Replay to the cloud is not implemented: frames queued while offline are not sent later. Packet loss and recovery time were not measured in a field test.

1. Local buffer
Telemetry is written locally before the Firebase mirror runs. A lost uplink does not stop the Pi's local dashboard or decision loop.
2. Local access
The dashboard is served by the Pi on the local network. No fixed hotspot address is quoted here; use the address shown by the running service.
3. No replay (not implemented)
The pdm-cloud service keeps up to 200 frames in a local file while the link is down and clears them after the next successful write. They are not sent to the cloud later, so there is no back-fill. The Pi keeps sampling and its local dashboard keeps updating. Loss was not measured.

Honest Defense Key

Judge Defense Master Key: Six Straight Answers

Use these six answers without upgrading a benchmark claim into a field claim.

Q1: Why didn't you just use an Arduino?

"The capstone brief excludes Arduino and the rig already uses I2C, SPI and I2S sensors plus a local Flask dashboard and Linux services. We chose a Raspberry Pi 4 for that integrated edge role. We did not benchmark an Arduino alternative, so we make no speed claim against it."

Q2: Why not stream all raw vibration directly to the Cloud?

"Streaming every raw window would increase bandwidth and expose raw signals; an offline link would also break the live view. We compute features on the Pi and mirror lightweight status frames. We did not measure cloud cost or end-to-end latency, so we do not quote either."

Q3: Why Random Forest over Deep Neural Networks?

"We did not benchmark deep networks locally, so we quote no CNN memory or latency number. Random Forest fits the small tabular feature set, has no verified per-window latency on the Pi yet, and gives inspectable feature importance. Its 100% score is synthetic-only."

Q4: How did you prove your sensors are accurate?

"A Pi-only six-face ADXL345 and two-point MAX6675 calibration procedure is implemented and documented, with backups and an honest certificate. No operator-run signed record exists yet, so we say REVIEW / UNVERIFIED, not PASS."

Q5: Is remaining useful life working?

"Not yet. We have no valid run-to-failure data for a whole motor, so we show no RUL number. Public bearing and turbofan datasets are different machines, and we do not present them as our result. The rig RUL script (ml/rul_from_rig.py) exists but has no valid whole-motor data to run on. This is an open item, not a pass."

Q6: Which data is actually real?

"Our rig is live Pi telemetry only, and no accuracy has been measured on it. The fault-detection benchmark is the HUST public bearing dataset (real 750 W bench motor, artificial 0.2 mm bearing cracks, CC BY 4.0): fault vs normal 99.86%, 7-class about 41%, exploratory and offline. The classroom 100% figure is synthetic only."
