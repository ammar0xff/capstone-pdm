01 · Project purpose and architecture

The capstone asks for a monitored industrial machine that senses physical condition, detects abnormal behaviour at the edge, communicates the result, and presents an operator decision within a fixed student budget. The system was built as an offline-first cyber-physical pipeline: the Pi can keep monitoring and serving a local page without the internet, while a zero-cost Firebase mirror provides remote visibility when networking is available.

ADXL345 (I2C) ─┐ MAX6675 (SPI) ─┼─► edge/edge_daq.py ─► Stage 1 SPC gate ─► Stage 2 RF ─► response plan INMP441 (I2S) ─┘ │ │ │ ├─► edge/cal.json ├─► Firebase RTDB mirror └─► latest_state.json └─► Flask / hosted dashboard

02 · Raspberry Pi setup

The Pi is the acquisition and inference host. The verified deployment uses user renad, path /home/renad/pdm and three systemd units. The exact service table, model copy and MD5 match are recorded in docs/PI_DEPLOYMENT_EVIDENCE.md.

2.1 Board and interfaces

  1. Install Raspberry Pi OS, set hostname/user, and enable I2C, SPI and I2S.
  2. Wire ADXL345 to I2C bus 1 address 0x53, MAX6675 to SPI0 CE0, INMP441 to the I2S card used by arecord.
  3. Keep the MAX6675 module away from the Pi heatsink; the cold junction is on the module. [NEED: measured placement and temperature log]
  4. Clone the repository into ~/pdm and create a Python environment or install the pinned stack.
cd ~/pdm
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v

03 · Firebase setup

Firebase supplies the zero-cost cloud mirror and the hosted presentation site. The project is castpone2026; the mirror writes the latest state packet to https://castpone2026-default-rtdb.firebaseio.com/motor1.json. edge/cloud_config.json stores the URL, 5 s interval and 15,000-write daily guard; edge/cloud_backlog.json holds writes while offline.

3.1 Creation steps

Create or select the Firebase project castpone2026.
Create Realtime Database and keep the path motor1.
Set firebase_url in edge/cloud_config.json and FIREBASE_RTDB_URL in public/index.html to the same endpoint.
Copy edge/pdm-cloud.service, reload systemd and start the mirror.
Deploy the presentation files with firebase deploy --only hosting.
firebase login
firebase use castpone2026
firebase deploy --only hosting
curl -s https://castpone2026-default-rtdb.firebaseio.com/motor1.json

3.2 Dashboard creation

There are two dashboard surfaces built from the same live state schema. The local Flask page in edge/templates/index.html is served by edge/dashboard.py on the Pi. The hosted page in public/index.html reads Firebase, draws the same charts, shows the operator decision, links to the exhibition deck and calibration explainer, and provides alarm mute. Neither page can write calibration data.

Security reality. The deployed RTDB rules are public read/write. Anyone with the URL can read or overwrite motor1. This was kept for exhibition telemetry and is documented in docs/FIREBASE_SETUP.md. No auth change was made during cleanup. [NEED: auth model and operator identities]
Safe migration. Enable authentication, write least-privilege rules, add a deny-unauthenticated-write test, move any token to a Pi-local environment source, then verify both writer and dashboard before switching rules.

04 · Data generation

Because a run-to-failure motor rig was not available, the team generated a physics-grounded synthetic benchmark with a custom dataset generator. ml/dataset_generator.py creates whole runs with seeded noise, then windows them into fixed-length rows saved as ml/windows.csv. A run ID column keeps every train/validation/test split disjoint: a run never appears on both sides of a split.

4.1 Classes and physical grounding

The generator does not integrate the bearing ODE it cites; it uses a bounded synthetic proxy.

4.2 Split discipline

train_rf.py uses StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42) grouped by run_id, plus a 70/15/15 whole-run hold-out: 1000 train, 200 validation and 200 test windows. tests/test_evaluation.py asserts zero overlap and balanced classes. This matters because random window splits would leak a run's noise pattern into the test set and inflate the score.

05 · AI model initialization and training

The model is a scikit-learn Random Forest, chosen because it is small enough for the Pi, works with tabular physical features and gives a confidence estimate. It is initialized by training in ml/train_rf.py and loaded at runtime by ml/rf_predictor.py.

5.1 Nine model features

FeatureWhy it was chosen
RMS, peak, crest factor, kurtosisEnergy and impulsiveness of the vibration window
Temperature, thermal slopeSlow thermal fault development
Acoustic RMS, peak, ZCRAudible rubbing/squeal and waveform sign-change proxy
Crest/spectral context featureAdditional time-domain shock indicator

z_score is deliberately excluded from the RF features. It is a Stage-1 gate metric derived from dynamic RMS; including it would leak the gate decision into the classifier. The metadata records this policy and the tests enforce it.

06 · Using the model: how and why it predicts

Runtime inference is a two-stage operation in ml/rf_predictor.py, called once per acquired window from edge/edge_daq.py.

1. Build feature dict from the current window 2. Stage 1: z = (rms_dyn - baseline_mu) / baseline_sigma - nominal window → return "Healthy", rf_executed=False - breach or thermal limit → continue 3. Stage 2: build the 9-feature vector → predict_proba → argmax 4. Attach response_plan (class, priority, action, timeframe, owner, rationale) 5. Publish in latest_state.json and to the dashboard/Firebase

Why this design

The coarse gate mirrors the triage idea in the literature: most windows are normal, so a cheap statistical check decides whether the more expensive diagnostic step is needed. On a nominal smoke-test window the wrapper returned rf_executed=False; on a synthetic breach it returned rf_executed=True with a class and response plan. No CPU percentage is claimed because no CPU measurement was taken.

The prediction is a four-class diagnosis, not a lifespan forecast. It can say “Bearing Defect” because kurtosis and crest factor show impulsive behaviour consistent with spall impacts in the generated model. It cannot say how many days remain. Remaining-useful-life regression would need a run-to-failure dataset with time-to-failure labels, which this project does not have.

08 · Calibration on the Raspberry Pi

Calibration is a physical procedure, not a dashboard action. edge/calibrate.py runs on the Pi while the motor is stopped and pdm-daq.service is down. The full runbook is docs/CALIBRATION_RUNBOOK.md.

ssh renad@<pi-address>
cd ~/pdm
sudo systemctl stop pdm-daq.service
python3 edge/calibrate.py
sudo systemctl start pdm-daq.service

8.1 What the script does

  1. Prompts for the operator name and samples six ADXL345 orientations (100 readings each).
  2. Fits one shared scale and three biases from the six-face means, using the same model as edge_daq.py.
  3. Samples ice and boiling reference points (12 readings each), asks for the measured boiling reference and offers a third thermal check.
  4. Validates every value: finite numbers only, correct face set, positive face differential, plausible scale/slope.
  5. Backs up the old cal.json, writes the new one atomically, saves a markdown run record and appends a JSONL log line.
